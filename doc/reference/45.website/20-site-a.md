# A 类站概述

**A 类站是「服务端动态渲染」的网站：目前没有实现，本文是设计桩子。**

如果未来要做，就从这里开始设计；现在读它，是为了知道我们曾经想过什么、将来大概往哪走。

## 原始设想

最初的想法是：A 类把整个域名交给一个服务端模板引擎，页面不是磁盘上的静态文件，
而是由模板根据当前请求动态生成的——比如商品详情页、用户主页这类内容随数据变化、
又需要稳定 URL 与 SEO 的页面。

当时的思路已经体现在 A 分支的机制里：过滤器按 hostmap 把路径重写到一个
「渲染入口」，由它查数据、跑模板、输出 HTML。但渲染入口一直没有实现，
`/www` 时代的站点模型也随 `cmd_www` 删除了。

## 为什么搁置

- 客户端网站的主流做法已经是 C 类静态站 + 动态 API，动态能力不依赖服务端渲染
- SEO 不是阻碍：SPA 用构建期预渲染等前端手段就能解决
- 一直没有真实需求，所以代码里始终只有 A 分支的「路径重写」，没有动态渲染的实现

## 与域名转发的关系

- A 分支的机制（hostmap 重写 + 服务器端 forward）见 [域名转发](10-domain-mapping.md)
- A 分支当前的实际用途只剩 `api.foo.com` 子域的接线（`/api/<域>/...`）；
  其实不建子域也可以，前端在 C 类域名上直接调 `/api/<域>/...` 同样生效，
  见 [C 类站](40-site-c.md)
- hostmap 的兜底规则 `^/(.*)$ => /www/${grp}/${1}` 是 www 时代的遗留：
  命中后是 200 空响应 + 日志 `Invalid Req`

## 技术方向（倾向）

**优先采用开源模板引擎，不再扩展自研的 `WnTmpl` 体系来做页面渲染。**

候选（占位参考，未做选型调研）：

- **Thymeleaf**：HTML 友好，Spring 生态标配，模板本身是合法 HTML
- **Pebble**：轻量，语法接近 Jinja/Twig，继承与宏都顺手
- **Freemarker**：老牌，功能全，文档与资料多

## 待设计清单

- 引擎选型（性能、模板安全沙箱、中文资料）
- 模板文件在域目录里的约定位置（与 C 类站的 `site` 目录什么关系）
- 渲染缓存与静态资源缓存的关系
- 与 regapi 的关系（动态页的数据直接查对象，还是反过来调自己的 API）
- 登录与权限衔接（渲染时能否拿到站点会话、按权限出页面）
