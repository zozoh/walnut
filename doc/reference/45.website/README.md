# 网站机制概述

Walnut 的「网站」就一句话：**给一个域绑一个域名，这个域名对公众提供内容**。

绑定靠 [域名转发](10-domain-mapping.md)：`WalnutFilter` 按请求的 `Host` 头找到
`/domain` 下的记录，把请求分流。内容分三种「站」，各有各的活法：

| 站 | 路径 | 内容谁提供 | 状态 |
|---|---|---|---|
| A 类站 | hostmap 重写 | 服务端动态渲染 | 搁置——设计桩子 |
| B 类站 | 原样 | `/a/login` 的定制登录页 | 在用——管理后台 |
| C 类站 | 原样 | `WnMainModule` 读静态目录 | 在用——客户端网站的主流 |

## 三兄弟的分工

- **[A 类站](20-site-a.md)：动态渲染站点**。最初的设想是用服务端模板引擎
  动态渲染页面；一直没有真实需求，目前是设计桩子，等将来设计。
- **[B 类站](30-site-b.md)：管理后台的自定义登录页**。给管理后台的域名
  换一套自己的登录界面，登录认证复用站点的用户库。
- **[C 类站](40-site-c.md)：静态站点 + 动态 API**。客户网站的标准做法：
  域名挂构建好的 SPA，动态数据调该域自己的 regapi 接口——一个域名全搞定。

## 先读什么

- 想搞明白「域名怎么变成站点」→ [域名转发](10-domain-mapping.md)
- 想参与动态渲染站点的设计 → [A 类站](20-site-a.md)
- 想给管理后台做定制登录页 → [B 类站](30-site-b.md)
- 想给客户建网站 → [C 类站](40-site-c.md)

# 总结

读到这里，「网站」这件事就是一句话：**域名转发负责认路，A/B/C 决定这条路上有什么**。
A 是一张留给未来的设计草图；今天真正在跑的，是 B（登录页）和 C（静态站）。
