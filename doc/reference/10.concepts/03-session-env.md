# 会话与环境变量

**会话（Session）是命令执行的身份载体**：登录即创建会话，
之后的每条命令，都在会话绑定的用户身份下执行。

这个想法是 Walnut 安全模型的支点：命令能做什么，取决于会话身份，
而不是谁发起了 HTTP 请求。会话的完整机制（对象结构、票据、过期、多级登录）
在 30.auth 中专门展开。

**环境变量**是会话级的名值对：命令行用 `$NAME` 引用，JS 里通过 `sys.envs` 访问。
它承担三类职责：**路径查找**（PATH/APP_PATH）、**行为开关**（THEME/OPEN）、
**业务上下文**（你自定义的任何变量）。

# 环境变量从哪来

一个变量的最终值，按下面的优先级层层覆盖，高优先级胜出：

1. **系统默认** —— 给新用户配的初始值
2. **用户持久化** —— `~/.env` 文件，登录时加载
3. **会话动态** —— 命令或脚本临时设置，会话过期即消失
4. **强制覆盖** —— `!NAME` 前缀，无视前序值（站点环境注入用它）

记住一个原则就够：**要长久就写 `~/.env`，要临时就动态设置**。
`env` 命令负责全部读写，具体子命令见它的手册。

# 关键变量举几个例子

- `HOME` —— 主目录，即 `~` 的展开值
- `PATH` —— 命令查找路径，含 `~/bin`（你的自定义命令放这里）
- `OPEN` —— 登录后打开的应用
- `APP_PATH` / `THEME` —— 应用查找路径 / 界面主题

完整清单不必在此背下，使用各模块时会逐一遇到。
