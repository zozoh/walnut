# 一切皆对象

`Walnut` 中**所有数据都是对象**，就像 `Linux/Unix` 可以用`文件/目录`来描述任何数据。
你完全可以把 `Walnut` 中的对象理解为 `Linux/Unix` 中的文件/目录。

一个 `WnObj` 对象有两种类型（`race`）：

1. 目录：`DIR`
2. 文件：`FILE`

一个 `WnObj` 被称为`标准对象`，它有两部分信息：

1. `元数据`：文件名、创建时间、修改时间、大小、类型等
2. `内容`：譬如一个图片的具体二进制内容

> 当然，如果一个对象是`目录`，那么它只有`元数据`，没有`内容`。

# `id` 对象的标识

每当你创建一个对象，`Walnut` 会为其分配一个唯一的 `ID`。
你可以把它理解为一个 `UUID`，它的形式譬如 `35a9hqpprcjf4q7fje9f2d4n52`。

通过 `ID`，你可以高效地获取到一个对象的全部元数据信息。
`ID` 全库唯一，永不变更；而路径是由树推导出来的视图——对象一旦被移动，路径就变了。

# `nm` 对象的名称

每个对象都会被指派一个名称（`nm`）。在同一级目录里，它必须是唯一的。
因此，你可以像普通文件系统一样，通过路径来访问它。

譬如在 `Walnut` 的控制台里，你可以：

```bash
bunya:$ cat ~/tmp/abc.md
Hello World!
This is ABC.md
```

# 对象的标准元数据

除了对象的两个最重要的元数据 `id` 和 `nm`，其他元数据我一次性列给你：

```json5
{
  //-------------------- 身份
  id  : "35a9hqpprcjf4q7fje9f2d4n52",  // 唯一 ID
  pid : "y4ne...",                       // 父对象 ID
  nm  : "abc.md",                        // 名称（同级唯一）
  race: "FILE",                          // DIR | FILE
  //-------------------- 权限
  c : "bunya",                           // 创建者（creater，仅记录）
  g : "bunya",                           // 所属组（grp）——对象属于哪个域
  m : 448,                               // mode 权限位（三段八进制，见下文）
  //-------------------- 内容：仅针对 FILE（目录无）
  tp  : "md",                            // 类型后缀（决定默认 MIME 和缩略图）
  mime: "text/markdown",                 // 内容类型
  sha1: "4e8a...",                       // 内容指纹
  len : 237370,                          // 内容字节数
  //-------------------- 结构辅助
  lbls: ["bug","A"],                     // 自由标签，可查询
  d0  : "home",                          // 所属一级目录名（加速范围查询）
  d1  : "bunya",                         // 所属二级目录名（通常=域名）
  //-------------------- 映射与链接
  mnt : "sql(demo:t_news)",              // 存储映射（见下文「对象的存储与映射」）
  ln  : "id:xxxxx",                      // 链接目标（见下文「链接对象」）
  //-------------------- 时间
  ct  : 1730265600000,                   // 创建时间（绝对毫秒）
  lm  : 1730265600000,                   // 最后修改时间
  expi: 1730269200000,                   // 过期时间（见下文「过期自动删除」）
}
```

对象上还可以有**任意自定义元数据**：业务字段直接放对象上（索引器支持按字段查询），
不用建表——这是 `Walnut` 作为业务基座的关键能力。
注意大字段内容不要放元数据，写进`内容`（桶），用 `sha1` 关联。

## mode：三段八进制，第一段是 admin

```bash
  admin    member   others
[r][w][x] [r][w][x] [r][w][x]
```

与 Unix 的关键差异：**第一段不是 owner 而是 admin**（属组的管理员）。
对象没有 owner 概念，只有 `c`（创建者，仅记录）和 `g`（所属组）。
设计动机是强调**组内协作**——一个域的数据由多人共同维护。

对象还能声明 `pvg` 元数据做更细的授权（按用户、按业务角色）。
完整的权限模型见 [三层权限](../30.auth/privilege.md)与[业务权限](../30.auth/biz-privilege.md)，
这里你只需要知道 `m` 和 `pvg` 这两个键的存在。

# 过期自动删除

通过元数据 `expi` 可以指定一个对象的过期时间（精确到毫秒）。
到时，对象会被回收任务自动清除。

我们这里不详细展开，你只需要知道：如果你指定了一个 `expi`，到了你指定的时间，
这个对象会自动被系统删除掉。

并且如果这个对象是一个`目录`，那么其内所有的子目录/文件也都会被删除。

如果你是一名经验丰富的开发者，我想你自然会知道，这个功能在很多场景下有多省事——
会话、验证码、订单超时、临时文件，都不用再自己起清理线程了。

> 具体的回收机制，可以参看 [过期对象机制](../20.io-storage/expiration.md)

# 链接对象

`Linux/Unix` 中的`链接文件`是一个很好的设计。考虑到 `Walnut` 的数据管理与
操作系统基本一致，那么它自然也需要支持`链接对象`。

它实现的方式非常简单，就是使用一个名为 `ln` 的元数据，指向对象链接到的位置：

```bash
drwxr-x---  bunya bunya     0 10  6 19:06  ddl -> /mnt/project/bunya/init/ddl/
```

在对象 `ddl` 里面声明一个 `ln` 元数据，值为 `/mnt/project/bunya/init/ddl/`。
那么你访问 `ddl` 对象，就相当于访问 `/mnt/project/bunya/init/ddl/`。

`ln` 的值有三种形态：

```bash
ln = "id:xxxxx"      # 按对象 ID 定位（最可靠，目标移动后仍然有效）
ln = "/home/demo/a"  # 绝对路径定位
ln = "sub/a.txt"     # 相对路径定位（相对链接对象所在的父目录）
```

访问链接时会顺着 `ln` 找到真正的目标；目标本身还是链接就继续展开，直到找到非链接对象。

```bash
ln -s ~/docs/readme.md ~/links/rm       # 创建链接
ln -s id:9mXkVf ~/links/rm              # 也可以直接写 id，更抗移动
rm ~/links/rm                           # 删除链接不影响目标
```

这里需要说明的是，你只能把`目录对象`链接到`目录对象`，把`文件对象`链接到`文件对象`。
如果你把`目录对象`链接到`文件对象`，或者反过来，你可能会遇到奇怪的错误。

在 `Walnut` 后续的版本中，它可能会对此进行更严格的检查，甚至都不允许你这样做，虽然现在你是可以的。

> 这是因为 `Walnut` 中的`目录对象`管理的是`元数据`，而`文件对象`管理的是`内容`。

# 对象的存储与映射

你可能还想知道对象的`元数据`与`内容`是如何被管理的。

这个话题我们会在 [数据存储与映射](../20.io-storage/README.md) 中详细展开。
你只需要知道：对象还有一个标准元数据 `mnt`，专门用来指定它的存储映射方式。
被映射的子树，其对象 `ID` 会变为两段式（`映射根ID:子索引ID`），对使用者完全透明。

# 总结

很好，如果你读到这里，我想对于 `Walnut` 中的对象，你应该就没有什么更多需要知道的了。

任何主要是 `CRUD` 的业务系统，在 `Walnut` 的视角里，其实本质无非是对于对象的**增删改查**。
