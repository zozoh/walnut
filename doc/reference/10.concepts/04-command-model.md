# 命令模型（沙箱、管道与三种写法） 概述
在 Walnut 里，**一切操作都是命令**。命令模型基本高仿 Linux/Unix：
有标准三流（stdin/stdout/stderr）、有管道 `|`、有重定向 `>` `>>`，
小命令可以拼装出大功能。

这个选择带来两个深远的收益：

- **模块化扩展** —— 新增功能就是新增一个 `cmd_*` 类加一篇手册，不动内核
- **命令即 API** —— 命令的三流天然映射 HTTP，一个文件就能变成接口（regapi）

# 执行模型

一条命令从输入到执行，经过这样一条链路：

```bash
用户输入命令行
   │
   ▼
WnRun（解析管道 |、重定向 >、变量 ${...}）
   │
   ▼
WnBoxService 分配沙箱（WnBox）── 每个沙箱绑定一个会话身份
   │
   ▼
JvmExecutorFactory 按命令名加载 cmd_* 类并执行
```

沙箱是命令的运行环境：三流、会话身份、IO 入口都装在里面。
命令只面对 `WnSystem` 接口，不需要知道自己在哪个线程、哪个 HTTP 请求里——
这就是「命令即 API」能成立的原因。

# 三种命令写法

命令按**写法（继承关系）**分三种模式，应对不同的复杂度：

- **简单命令** —— 一个源文件，参数进来、结果出去，大多数命令属于这种
- **复杂命令** —— 子命令是独立的类，关键逻辑封装为服务类供其他模块复用
- **过滤命令** —— 子命令是 `@过滤器`，共享一个上下文对象，按顺序加工、任意搭配

三种写法怎么选、怎么实现，是 40.commands 的主题；
那里还有全部命令的清单，以及每篇手册的存放位置。

# 管道与重定向

管道让前一个命令的 stdout 成为后一个的 stdin，重定向把输出写进对象。
两者加上变量替换，就是 Walnut 的「胶水语言」：不写代码，
一条命令行就能完成过滤、统计、批量修改。

执行细节（变量替换规则、`run` 命令、缓冲区语义）有专门文档展开。

# 帮助系统

每个命令都配中文手册，与源码同包存放，运行时 `man` 直接查；
`cmds` 列出全部可用命令。域用户还可以在 `~/bin/` 放同名脚本覆盖系统命令。
