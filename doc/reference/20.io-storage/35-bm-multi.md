# 桶管理器 - multi

> **状态：规划中，暂未实现。** 源码中没有 `multi` 桶管理器的实现类。

## 设计意图

前面的桶管理器都是「一个子树固定一种介质」。`multi` 想解决的是**动态选择**：

根据一个配置文件和当时的上下文（对象大小、类型、所在目录），把不同的内容
分流到不同的桶里。想象这样的规则：

- 小文件（< 1M）→ [sha1](30-bm-sha1.md) 本地桶，读得快
- 大文件 → [vxds](31-bm-vxds.md) 对象存储，存得便宜
- 临时文件 → Redis，自动消失

一次写入，系统替你选最合适的介质；读取时按对象元数据里记录的位置找回。
对使用者仍然完全透明。

## 规划中的语法

```bash
mnt : "://multi({规则配置名})"
```

规则配置预期存放在 `~/.io/bm/{规则配置名}.json`（与 Redis 桶配置同目录）。

在实现落地前，以上语法仅供参考，不要用于生产配置。
