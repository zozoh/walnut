# 架构与运行机制

## 分层视图

```bash
┌─ Web 层 (web/) ── Nutz MVC
│   WnMainModule(@Modules by ioc:webscan)  ← 入口
│   ├─ AppModule   /a/*     应用打开、登录、run、beacon_run
│   ├─ UsrModule   /u/*     登录/登出/会话切换(chse)
│   ├─ ObjModule   /o/*     缩略图、下载等对象访问
│   ├─ GuestModule /g/*     访客接口
│   ├─ FuseModule  域名转发(hostmap) → /www/{grp}/... 或 /api/{grp}/...
│   └─ filter: FuseActionFilter / WnAsUsr / WnCheckSession / WnSetSecurity
├─ 命令执行层 (util/WnRun + impl/box)
│   WnRun.run() → WnBoxContext(会话+Io+services+attrs)
│   → JvmExecutorFactory 查找 cmd_* → JvmExecutor.exec(WnSystem)
│   WnBoxService: 命令沙箱(box)，线程切换用户权限执行
├─ 核心服务层 (login/ + api/ + core/ + impl/)
│   WnLoginApi(usr/role/session 三组 Store，可 SQL 或本地实现)
│   WnIo(树/索引/桶/句柄) ← WnIoImpl2 + WnIoMappingFactory
│   WnHookService(钩子), WnLockApi(锁), WnSysCronApi/ScheduleApi/TaskApi
├─ 扩展层 (ext/)  161 个命令的业务逻辑主力
└─ 存储层: MongoDB(主索引) + Redis(锁/句柄/引用计数/BM/MQ) + SQL(可选映射)
```

## 启动流程（WnSetup）

1. `WnCheckRootSetup`：检查 root 账户
2. `WnMakeSysFolderSetup`：建立 `/sys/*`、`/var/*`、`/etc/*`、`/bin`、`/home` 等系统目录
3. `WnCleanExpiredSetup`：过期对象清理线程（EOT, Expired Object Table）
4. `WnCleanExpiObjTableCleaner`：EOT 表自清理
5. `WnMqSetup`：注册 MQ 消费者（cron/schedule/task 后台线程由此驱动）
6. `WnRunTestSetup`：自检

后台线程（web/bgt/）：`WnBgRunCronConsumer`（每分钟把 cron 展开成分钟槽）、`WnBgRunScheduleConsumer`（把分钟槽任务推入任务栈）、`WnBgRunTaskConsumer`（消费任务栈执行命令）。

## IoC 配置（conf/ioc/*.js）

- `conf.js`：PropertiesProxy（web.properties 等）
- `mongo.js`：MongoDB 连接（主索引 obj 集合、refs 集合）
- `redis.js`：多组 Redis 配置（锁/句柄/引用/BM/MQ 分开）
- `io.js`：核心 bean——`globalIndexer`(MongoIndexer)、`globalBM`(LocalSha1BM)、`ioHandleManager`(Redis)、`ioMappingFactory`，以及 mem/mongo/redis 替代实现（`lockApiByMemory`、`ioHandleManagerByMemory`、`redisBM`），单机和集群环境可切换
- `service.js`：loginApi、taskApi、cronApi、scheduleApi 等服务注册
- `mq.js`：消息队列实现选择

## 关键抽象（api/ 44 个文件）

- `WnObj`：一切皆对象。核心字段缩写体系（id/pid/nm/race/tp/mime/sha1/len/c/m/g/md/d0/d1/lbls/ct/lm/expi/mnt/ln…），与 Unix 神似：第一段 mode 是 admin（非 owner），强调组内协作。
- `WnIo`：对象树 + 句柄读写。方法族：fetch/get/create/write/read/open/flush/close/setBy/inc/aggregate/copy。
- `WnQuery`：查询抽象（pid/regex/limit/skip/sort），被所有索引器实现。
- `WnIoIndexer` / `WnIoBM` / `WnIoHandle`：索引器 / 桶管理器 / 读写句柄三分离。
- `WnExpiObjTable`：过期对象表（多节点抢占清理）。
- `WnLockApi`：通用锁（Redis Hash / 内存实现）。
- `WnHook`：钩子（create/write/delete/move/meta/mount 六类，全局先于用户）。
- `WnBox/WnBoxContext/WnBoxService`：命令执行沙箱与上下文。
- `agg/`：聚合查询（group/count/sum + transMode），支持多级分组。

## 命令系统

- 基类：`JvmExecutor`，实现 `exec(WnSystem sys, String[] args)`。
- `WnSystem`：命令运行时环境（in/out/err、io、session、auth、me、params、envs）。
- `man` 命令：每个 cmd 可在 `impl/box/cmd/man/zh_cn/` 配中文手册。
- 命令查表：`JvmExecutorFactory` 按 `cmd_` + 名称加载；域内可用 JS 覆盖同名命令（`~/bin` 在 PATH 中）。
- 管道与重定向由 `WnRun` 的命令行解析（`Cmds`/`WnEvalHelper`）完成。

## JS 执行（jsexec/）

- `JsExec`：Nashorn 兼容层，JS 里可访问 `sys.io/sys.exec/sys.me/sys.se`。
- `DomainGlobalJsCache`：域级全局 JS 缓存（域目录下的公共 JS 库）。
- 典型挂载点：钩子(.js)、cron 任务、cron_task 命令体、`@FILE` 内容、`thing.js` 的 onCreated/onUpdated 等。

## 值得注意的实现细节

- `WnLoginApi` 三级存储（usr/role/session）均提供 Std(本地文件) / Sql 两种实现，`WnLoginApiMaker.forHydrate()` 根据站点目录元数据动态构建（域站点账户库）。
- `WnBoxContext.auth()`：若会话带 site 路径，则用站点配置构建域内登录 API，否则用系统级——这是「域账户登录系统」的实现枢纽。
- `security/` 模块仅 10 个文件（建设中），对应 README「安全权鉴（建设中）」。
- `jdbc/` 已弃用（5 个文件），README 亦注明。
