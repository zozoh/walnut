# 文档规划思考（讨论稿）

## 读完项目后的核心判断

1. **Walnut 的本质是「命令 + 配置约定 + 目录布局」三位一体的系统**。对它的用户（二次开发者/站长/AI Agent）来说，最有价值的文档不是 Java API 文档，而是：
   - 目录布局约定（`/sys/*`、`~/.regapi`、`~/.dao`、`~/.domain`、`~/.weixin`...）
   - 元数据约定（`mnt`、`www`、`pvg`、`expi`、`api-*`、`http-*`、`cache-*`...）
   - 命令手册（161 个命令）
   - 配置语法（thing.js、dsync.json、XAPI 配置、运费表、WnCron、动态校验语法）
2. **读者分三类**：建业务接口/数据应用的人（regapi/sqlx/SQL 映射/通用实体/支付）、运维的人（存储映射/cron/MQ/同步备份）、二次开发的人（Java 库/WnIo API/命令扩展）。文档应按这三条线组织入口。
3. **AI Agent 友好 = 结构化 + 可检索 + 有确定性的路径约定**。Agent 最需要的三样东西：全文索引清单（每篇文档的 front-matter）、目录/元数据速查表（约定类知识密度最高）、命令-场景对照表。

## 文档体系提案（v2，基于实际通读修正 v1）

### 组织原则

- 不按代码包结构组织（那是源码地图的事），按「使用者任务」组织。
- 保留现有分层编号体系（`xx-l0/l1` 前缀），它有助排序和 grep，但目录改为按任务域命名。
- 每篇文档 front-matter 增加机器可读字段（module/keywords/source）。

### 目录结构提案

```bash
doc/_old/markdown/
|-- README.md            # 三类读者的任务入口（人读）
|-- INDEX.md             # 全量清单：路径|标题|keywords|源码模块（AI 读）
|-- SOURCEMAP.md         # 源码包 ↔ 文档双向映射（改代码/查实现用）
|-- 000.quick-start/     # 30 分钟跑起来 + 第一个 API + 第一个定时任务（新建）
|-- 100.concepts/        # 核心概念：一切皆对象/命令机制/域与环境变量（现 core-l0 重写+补空壳）
|-- 200.io-storage/      # 存储映射体系：索引器/桶/句柄/mnt 语法/去重/过期（现 c0-io 扩写）
|-- 300.auth/            # 账户/会话/权限三层/域账户/自动登录/验证码（并入 draft 抢救内容）
|-- 400.commands/        # 命令手册（按场景分章：文件对象/数据处理/媒体/网络/系统/工具）
|-- 500.regapi/          # HTTP 接口：API 对象/请求对象/缓存/权限/preload（现 c1-regapi 已好，补实战）
|-- 600.data/            # 数据应用：sqlx/SQL映射(.dao,.io/ix)/通用实体(like,favor,score,history)/xo
|-- 700.sched-async/     # 定时任务(WnCron语法)/分钟计划/任务栈/MQ/钩子/通知
|-- 800.integrations/    # 支付/微信/支付宝/阿里云/短信/邮件/XAPI/数据同步（现 func 重组）
|-- 900.ops/             # 部署/域名映射/备份恢复(bulk)/dsync/回收站/运维命令
|-- 950.dev-guide/       # 二次开发：Java 库模式/自定义命令/man 手册/JS 脚本 API(cheap解析器)
```

（编号仅为排序方便，最终命名可议。）

> ❌ 不含：www 站点模型、Thing 数据集、商城——作者确认弃用（cmd_www 已删），
> 现有 webs-l0/webs-l1/thing-l0 文档归档不迁移；Thing 的 17 篇 man 手册保留在源码中作存量参考。

### 三个关键动作（按优先级）

1. **抢救信息**：draft 中仍有价值的机制文档并入正式区（清单见 06 篇）：hook、vcode、token、auto_login、env、sysconf、thumbnail。
2. **补齐最大缺口**：数据操作线（sqlx、.dao 数据源、SQL 映射定义）和整合线（mailx、XAPI、支付回调实战）——这是弃用 Thing 后用户建数据应用的主路径。
3. **建立索引**：INDEX.md + SOURCEMAP.md 半自动生成（脚本扫 front-matter 生成），保证文档不腐烂。

### 与前版（doc/reference/README.md v1）的主要变化

- v1 按 `core-l0~l2 / ext-*` 代码视角组织；v2 改为按任务域组织——用户（人/Agent）按任务找答案，代码映射交给 SOURCEMAP.md。
- **v2.1（本轮）**：删除原 600.site-app（www/thing/商城，已弃用），新增 600.data 承接数据应用主路径（sqlx/SQL 映射/通用实体/xo）。
- 新增 000.quick-start 和 950.dev-guide 两端：上手体验和扩展开发是 AI Agent 场景的高频入口。
